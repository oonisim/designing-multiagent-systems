## Section guide

### 14.1–14.2 Problem and architecture

Start with [`test_workflow.py`](../../examples/workflows/yc_analysis/test_workflow.py),
then read [`workflow.py`](../../examples/workflows/yc_analysis/workflow.py).
It shows the graph and data flow before implementation details.

### 14.3 Data preparation and cheap filtering

Read [`models.py`](../../examples/workflows/yc_analysis/models.py), then the
data-loading and filtering functions in [`steps.py`](../../examples/workflows/yc_analysis/steps.py).
The workflow narrows data with deterministic work before model-based analysis.

### 14.4–14.5 Structured analysis and results

Continue through the analysis steps in [`steps.py`](../../examples/workflows/yc_analysis/steps.py).
Trace their typed outputs back into [`workflow.py`](../../examples/workflows/yc_analysis/workflow.py)
to see what each subsequent step consumes.

## End-to-end trace

```text
test_workflow.py → models.py → steps.py → workflow.py → workflow engine
```

Run the application only after configuring its inputs and model provider. Keep
the test as the first source of truth for expected structure.
